# Glassmorphism and service audit — 2026-10-03

The final direction is glassmorphism with native vector icons. Runtime UI source
contains no emoji. Incoming message content is preserved; messages are not
filtered or rewritten to remove user-supplied emoji.

## UI

Glass cards now share a translucent fill, a single subtle border, and small
shadows over a softened mint/blue background. Optical double rims were removed.
Both themes retain readable text, full-width switches, scalable buttons, and
expandable diagnostic controls. Contrast checks over actual surface/canvas
combinations exceed 4.5:1; minimum supporting-text contrast is 5.50:1 in light
mode and 6.15:1 in dark mode.

## Service

| Finding | Final behavior |
| --- | --- |
| BLE transitions started or stopped the service, including background starts. | The visible activity starts the foreground service after permissions are granted. |
| Adding the listener during creation could immediately stop a disconnected service. | Establish the notification channel and foreground state before adding the listener. |
| A lost connection stopped the service during automatic reconnection. | Keep the service running with an accurate waiting/connecting notification. |
| Connected startup triggered sync work more than once. | Apply connection sync once per connected session. |
| Users could not directly start/stop the service in settings. | Show actual running state and a native play/stop control. |
| Reopening the app could reconnect after an explicit stop. | Persist the stop choice and honor it on activity creation/resume. |
| Wake lock acquisition preceded a valid connection. | Hold the wake lock while connected; release on connection loss and destruction. |

The notification listener remains an Android-managed service and requires the
user to grant notification access in system settings. The app does not bypass
this permission. No backend/web server is part of this Android project.

## Verification

Eight isolated Robolectric checks pass: four native UI render/state checks and
four foreground-service lifecycle checks. Service tests cover startup without
an ESP32, connection loss, wake lock release, stopping via notification, and
remaining stopped when the activity reopens.

`assembleDebug` and `lintDebug` complete successfully. Lint reports one existing
error (`ExpiredTargetSdkVersion`, target SDK 32) and 65 warnings; the Gradle
configuration does not abort on lint findings. This is not a clean lint report.

The APK was installed and launched on the Android 9/API 28 emulator
`emulator-5580`. Live checks confirmed:

- `BleForegroundService` has `isForeground=true` and notification ID 1001.
- Its notification uses `drawable/ic_bluetooth` and accurately says it is
  waiting for an ESP32.
- Notification access was enabled in this isolated emulator, and Android bound
  `NotificationReceiverService`.
- The settings stop button removes the BLE service. Reopening the activity
  preserves the stopped state and shows the native play control.
- Starting again restores the service, which remains foreground after Home.
- Home and settings screenshots show the native icons correctly; AndroidRuntime
  logs contain no crashes during these checks.

The emulator and service are left running. The emulator has no Bluetooth
hardware, so physical ESP32 connection and notification delivery remain
unverified. The UI uses translucent native shapes over a softened background;
it does not implement real-time backdrop blur.
