# Full UI audit and visible glassmorphism — 2026-10-03

The previous result still resembled opaque white cards: the main light fill was
81% white, the navigation was 91% white, and there was no blurred backdrop.
This pass replaces the surface system across the whole native Android UI.

## Scope and findings

| Area | Finding | Change |
| --- | --- | --- |
| Page canvas | The pale gradient barely changed across a card. | Use continuous mint/blue folds that remain visible through glass. |
| Device status | A white hero looked like the other cards. | Use a translucent hero tint over the cached blur; keep real connection state prominent. |
| App filters | The surface was opaque and detached from the canvas. | Use the common glass panel; preserve full-row switches and native ripple. |
| Notification activity | Solid nested rows added visual weight; sender names truncated. | Use glass insets and put the wrapping sender below app/time metadata. |
| Message test | Inputs and card used different solid materials. | Use the common panel and translucent outlined input fills. |
| Time, weather, navigation | Repeated cards had no larger task grouping. | Add “Uji perangkat”; retain collapsible controls and theme-aware glass previews. |
| Background service | The surface did not follow the requested aesthetic. | Apply the same glass material; preserve actual state and native start/stop controls. |
| Notification permissions/help | Nested white panels competed with the main card. | Use lighter insets, one border, and translucent secondary buttons. |
| BLE saved device/discovery/list | Details and list items used solid surfaces. | Share glass panels/insets and native vector icon treatments across every row. |
| Bottom navigation | An almost opaque fill and scrim obscured the glass direction. | Replace with the sampled backdrop, a stronger glass tint, and one rounded edge; remove the scrim. |
| Large text | “Pengaturan” broke in the middle at 2× text on 320dp. | Use 26sp medium page headings; the tested word now fits without truncation. |
| Status/navigation color | Lower opacity reduced some label contrast. | Darken light-theme semantic colors and lighten dark-theme status labels; verify composition. |
| Icon rendering | Raw ImageView tint differed between runtime and plain layout inflation. | Use explicit AppCompatImageView and supported app:tint. No UI emoji. |

The design keeps the product's mint identity, real content, standard Android
icons, familiar actions, and readable spacing. There are no invented statistics,
marketing sections, decorative icons, bouncing effects, or animated wallpaper.
Cards remain where they group independent controls; they are not added simply
to fill space.

## Implementation and limits

`GlassBackdropView` generates the canvas and its Gaussian-like blur using three
separable box passes. `GlassSurfaceDrawable` samples the shared bitmap in window
coordinates. Fifteen page panels, both row layouts, and bottom navigation use
the material. Inputs and secondary actions are translucent; primary actions
keep a clear green fill. Light main-panel tint ranges from 15% to 40% white.

This is bitmap blur of the static decorative canvas. It does not capture or
blur messages, other apps, or content underneath navigation. Quarter-resolution
bitmaps are regenerated only on viewport resizing, and drawing reuses the
cache. There is no added runtime dependency or continuous blur workload.

## Validation

Ten isolated Robolectric checks pass, covering native rendering in both themes,
320dp with 2× text, landscape/tablet layouts, feature reachability, state restore
with motion disabled, service lifecycle, actual blur/caching, and composed
text/status contrast. The harness is at `D:/DevCache/smartnotif-ui-check` and
does not add test dependencies to the application build configuration.

Conservative floating-point composition gives supporting text a minimum
contrast of 4.73:1 in light mode and 5.05:1 in dark mode. The native AndroidX
composition test checks every text/status role against 4.5:1 in both themes.
This is not a claim of complete accessibility certification.

The debug APK was installed on `emulator-5580` (Android 9/API 28), and actual
home/settings screens were inspected in both themes. Service state remains
foreground, notification access remains bound, and AndroidRuntime logs show no
crash. Existing lifecycle tests confirm stopping is remembered and starting
restores the service. Physical ESP32/BLE delivery remains unverified because
the emulator has no Bluetooth hardware.

`assembleDebug` and `lintDebug` complete successfully. Lint has one existing
error (`ExpiredTargetSdkVersion`, target SDK 32) and 57 warnings; no newly
introduced lint errors remain. This is not a clean lint report.

Delivery artifacts are in `app/build`: `outputs/apk/debug/ESP32-SmartNotif-Glassmorphism.apk`
and `ui-review/index.html`. The gallery separates actual emulator captures from
native layout fixtures and labels the long-message/device examples as test
content. The emulator and foreground service are left running. Main/Primary
was not changed.
