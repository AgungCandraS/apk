# Pearl + Cobalt implementation review

User decision: direction B, selected after the reference/audit discussion.
This supersedes the earlier mint glass direction in DESIGN.md.

## Delivered

- All semantic color roles now follow pearl/cobalt, with a paired blue graphite dark theme. Actions are visually distinct from success status. System bars, inputs, switches, navigation, disabled controls, surfaces and launcher icons follow the new palette.
- Plus Jakarta Sans is bundled locally in four weights; support and framework font-family attributes cover the app's API24 minimum. Licenses are included. MAC/payload metadata may use native monospace.
- Material outlined vector icons provide a coherent family, including the three-tab navigation. A native memory-chip launcher replaces the raster launcher references for supported devices. No emoji is used for UI icons.
- Beranda contains connection, readiness, filters, and latest activity. The direct connection action opens the Bluetooth section and resumes discovery after runtime permission approval.
- Alat contains message, time/battery, weather, and navigation tests. Payload/details remain expandable. Shared delivery feedback appears above the modules; weather acquisition has loading/failure feedback and prevents duplicate requests while loading.
- Pengaturan retains service, notification access, restricted-settings help, app info, and device management.
- A separate activity detail surface contains the full log and clear action. Both Android Back and its visible back button return home. Preview content is truncated only on Beranda; full content remains in the log detail.
- Test messages show queued/sending feedback until a write result arrives. The UI no longer immediately describes queued data as sent. Duplicate payloads update pending entries in FIFO order; empty messages show a field error.
- Panels use 22dp radius, inner surfaces 18dp and buttons 14dp. The cached native blur renderer continues sampling a static decorative canvas; no live content capture or per-frame blur is introduced.
- Large text hides the decorative connection icon to give the device heading full width. Each tab owns a separate scroll surface; measured navigation clearance protects the bottom controls.

## Limits

- The emulator has no usable BLE adapter. A physical ESP32 connection, GATT delivery, firmware ACK and OLED display were not tested. Delivery success/failure callback handling was tested in the harness, not represented as a hardware result.
- Lint is not clean: the existing expired targetSdk32 finding remains, plus 60 warnings including legacy and formatting findings. The project's lint configuration allows the build to finish. A target-SDK/dependency migration was not included in the visual redesign.
- Cached bitmap glass blurs the decorative canvas, not live screen content. Contrast checks cover palette composition, not complete accessibility certification or every physical display.
- Full log content remains in the Activity's existing in-memory lifetime; this change does not add persistent log storage.
